# 设计原则：证据与记忆分离

新会话一开，上一次已经确认过的事实就消失了：

| 症状 | 有了它 |
|---|---|
| 同一道配置反复查 | `mem recall "网关 发版配置"` 带回上次的结论 |
| 修过的问题再跑一遍 | `mem recall "依赖 升级失败"` 带回 root cause 与修复命令 |
| 跨 agent 记忆孤岛 | Claude Code 修过的 bug，Codex 接着做时能看到 |

它不做 LLM 蒸馏，也不写知识库。**保存证据，在查询时生成记忆**——这两件事分开，是整个设计的起点。

## 什么时候值得查历史

判据比「重要 / 不重要」更好：**换个地方能不能免费重读到？**

当前文件内容、`git status`、屏幕上的数字，随时能重读，不值得查；只有推导才存在的东西——为什么这么定、踩过的坑、验证过的规则——不查就消失了。我们不引入模型判断显著性，但 `mem-recall` 的触发条件和跳过词表都服务这条判据。

## 三层视图

| 层 | 内容 | 体积 | 进模型吗 |
|---|---|---|---|
| **证据层** | 全部 user / assistant 文本 + 工具记录 | 数百 MB | 否 |
| **检索层** | 命中的会话，抽问题行 + 最新结论行 | ≤2 KB | 是 |
| **笔记层** | 显式 `remember` 的条目 | 几 KB | 是 |

## 为什么存全量

1. **蒸馏不可逆。** 索引时丢掉的内容以后找不回来，而你现在不知道三个月后会问什么。
2. **蒸馏会错，且无法自纠。** 只存结论，出错后没有原始上下文可回源核对。
3. **成本不对称。** 全量索引是一次性的本地 CPU 成本（数 GB transcript 分钟级建完，之后增量只处理变化文件）；漏掉的信息买不回来。
4. **蒸馏可以后补，全量不能后补。** 先存证据，蒸馏永远只是其上的一层视图。

## 为什么只注入一小块

实测抽样中，Claude 会话里只有约 5% 的文本是决策性结论，其余是任务描述、过程叙述与状态汇报。Anthropic 的 Pokémon 实验里，Sonnet 3.7 把每场战斗、每个道具、当前金钱与地图位置都写进记忆（413 文件 / 225 文件夹 / 1 枚徽章）——这些**每轮都能从屏幕重读**，记下来只会不断过期；Fable 5 只写策略、计划与验证过的规则（9 文件 / 2 文件夹 + `global.md` / 4 枚徽章），因为它们**只有推导才存在，不写就消失**。差距不在记得多或少，在记的是不是可免费重读的状态。

证据层再大，也只在查询时用来定位；进入模型的是从命中会话里抽出的少量结论行。

## 错误消息怎么处理

- 旧结论按 `0.5 + 0.5/(1+ageDays)` 自动降权；
- 同一会话取**最新**决策行，不取最早的；
- 显式 notes 权重 1.25×，提升到来源会话之上；
- 注入块带来源与日期（`来自 codex 会话 · 2026-11-09`），模型读到的是「当时这么说」，不是「现在的事实」；
- **助手说错的话永远不会自动变成 notes**——只有显式 `remember` 产生记忆条目。

## 数据边界

存的是**语义内容**，不是原始字节流：

| 存 | 不存 |
|---|---|
| 用户消息文本 | thinking / reasoning 中间块 |
| 助手消息文本（不含 thinking） | 系统 prompt、attachment、世界状态 |
| 工具调用名与命令（`Bash: git status`） | 重复的 API request blob |
| 工具输出、编辑与文件路径（按 role 标记） | 超长单行（>2 MB）与损坏行 |
| 时间戳、cwd、session id、模型名 | |

工具记录入库，但**按 role 分配预算**：查询时先花在人话上，工具记录只在人话不足时补位。理由是 transcript 里的 `tool_result` 是**那一次**执行的输出——临时文件、已删的构建产物、当时的 CI 日志，原处多半已经没了，「需要时重读」并不成立。全量索引拿回召回率，role 预算防止单个长会话占满名额。
