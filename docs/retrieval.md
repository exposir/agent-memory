# 检索算法

## Tokenizer

小写 → 按非字母数字切分（ASCII 保留 `- _ . /`）→ 标识符内部词拆分（`getUserProfile` → `get user profile`）→ 中文字符连续出现则拆为所有相邻 2 字二元组 → 去停用词。

```text
"星轨之外"    → 星轨 轨之 之外（无停用词命中）
"gateway 发版" → gateway 发版
```

## 查询归一化

`normalizeQuery` 在分词前做两件事，search 与 recall 共用：

1. **会话前缀截断**：首个冒号前是 ≤40 字的短前缀、以话语标记（一下 / 请问 / 问一下 / 想问 / 想问下 / 顺便问 / 请教 / 时 / 的时候 / 场景 / 情况）结尾，且冒号后 ≥10 字、不短于前缀时，只保留冒号后的内容。内容标签（「修复清单：」）和路径前缀不截。
2. **路径提示**：摘掉「（相关路径：X）」，X 不进入查询词，只作为路径约束参与加分。

```text
"想确认一下：alpha beta gamma"           → alpha beta gamma
"独立验证第 1 轮给出了修复清单：out/..."   → 原样（内容标签）
"alpha beta（相关路径：/repo/src）"        → 查询 alpha beta，路径 /repo/src
```

分词后还有三层**语料词表纠错**：

- **纯 ASCII 词**：只对 `df=0`、4–19 字符的词枚举同长替换与相邻换位，候选要求 `df≥5`；查询内其它词或复合段能支持时优先，否则要求最高候选频次 ≥ 次高 2×。复合段（`acme-eaily`）修好后回填到其余段。
- **路径段**：`df=0` 的带 `/` 词逐段枚举编辑距离 1 变体，但只有**整条变体路径**在语料里存在才进入候选；唯一或 ≥次高 2× 才接受，修好的段回填到拆分 token。只改单段不看整条路径，会把 `verify-r1.json` 纠到别的目录。
- **中文连续 run**：2–4 字 run 的相邻二元组中有 `df<10` 的罕见项时，枚举字符全排列；要求每个结果二元组 `df>0`、最小 `df≥20`、总 log 频次 ≥ 原串 1.5×、最高分唯一。`认默模型` 由此修到 `默认模型`。

OOV 状态在纠错前记录，human fallback 仍按「有 OOV」选择每会话窗口。三层都只在存在唯一或压倒性优势候选时改写，拼不出可信结果就保留原词。

## 候选与排名

不做严格 AND——自然语言查询里的填充词会让 AND 大量漏召回。改为 **IDF 加权排名**，项目内取 32 个候选，每个候选带 `matched`（命中信息词数）/ `strong`（其中稀有词数）/ `naming`（命中命名性词数）三个计数。

FTS 阶梯：exact → stemmed → CJK bigram → **focused** → relevance OR。focused 只在查询超过 8 个有效词时生效：取 IDF 最高的 8 个已收录词做 AND，命中即可，避免长查询直接掉进「任意词命中」的 OR。OOV 词（拼写错误、语料里没有的标识符）不进入 focused，也不能被门槛要求。

```text
BM25: k1 = 1.2, b = 0.75, delta = 0.1   // BM25+ 下界，抵消长会话的长度惩罚
doc.length = min(sqrt(matchedLength × session.words), 2 × avgWords)
userRoleBoost = 1.3   // 用户消息中的词频多计 30%
```

| 乘数 | 值 | 触发条件 |
|---|---|---|
| `decisionBoost` | 2.0 | 助手消息含决定 / 结论 / 根因 / 修复 / 改为 / 已解决等决策标记（中文词表按本机语料扩充） |
| `pastePenalty` | 0.5 | lead 词只由 ≥8 行、低多样性（去重率 < 0.35）的粘贴消息携带 |
| `directQuestion` | 1.1 | 匹配消息里有 ≤300 字的用户消息，且命中 ≥2 个最高 IDF lead 词；或该候选会话命中 lead 词的 ≤300 字用户消息中前 8 条里有 ≥2 个本会话 lead 词 |
| `promotedNoteBoost` | 1.25 | notes 条目提升到来源会话之上 |
| `freshnessDecay` | 0.5 + 0.5 / (1 + ageDays) | 无时间戳 / 异常时间 = 中性 1.0 |
| `proximity` | 1 + 0.35 × 200 / (200 + span) | span = 单条消息里全部查询词的最小字符窗口 |
| `titleBoost` | 1 + 0.4 × (标题命中数 / 查询词数) | `title` 非空即生效，不按 agent 类型特判 |
| `wornBoost` | 1 + 0.10 × log₂(1 + n)，上限 1.5 | 同一 session 被召回过 n 次 |
| `pathBoost` | 1.05 | 查询带路径提示，且候选会话在 `session_terms` 里覆盖路径的全部 token（至少 2 个） |
| `nonPathHitScale` | 0.6 | 查询里有 `df>0`、`idf≥3.5` 的路径词（只取最稀有的 1 个），候选会话未覆盖该路径词 |

`pastePenalty` 按查询证据判定，不看会话级 `pasted` 标记：正常提问旁边恰有一段粘贴，不该把整个会话降权；只有 lead 词只出现在低多样性长粘贴里才罚 0.5。`directQuestion` 奖励「历史会话里原样问过」的候选，扫描范围不只是已匹配消息，还包括命中 lead 词的短用户消息中每个候选会话的前 8 条——否则真正问过问题的那条消息落在窗口外就看不到。路径词是查询自带的物理实体：显式「（相关路径：X）」用 `pathBoost` 加成，查询词本身就是稀有路径时用 `nonPathHitScale` 压低未覆盖它的候选；只取最稀有的 1 个，因为公共前缀会同时出现在竞争会话里，要求全部路径词等于没有约束。`doc.length` 上限避免 BM25 长度项把真正讨论主题的超长会话压到后面。

`gaveUpPenalty = 0.5` 只属于结论质量信号：在 recall 选结论槽时降权，不乘入 search 的会话相关性分数。一次尝试失败后仍可能在同一会话里得到正确答案。

排序：`score desc → updated desc → session id`。

## 判定门槛

- `matched < 1` → 不显示；
- 问题里有语料库认识的稀有命名词 → 命中该词即可；
- 否则要求 `matched ≥ 2`；
- lead 词（IDF 最高的最多 3 个）必须出现在**人话**里，且一条消息里凑齐两个——除非某个词本身就是命名性标识符（`pgbouncer`、`v11`、路径）。

最后一条防的是长会话里「每个词都散落在不同角落、只被工具打印过」的假匹配。

当查询含 OOV 词时，focused 会丢掉该词再匹配；为了不让长会话的人话被一个全局 128 行窗口截掉，fallback 改为每个候选会话各取最多 4 条命中的用户/助手消息。没有 OOV 时仍用全局窗口，避免引入新的候选。同长 OOV 纠错成功后查询词可能已全部收录，但原查询带 OOV 这一事实已被记录，fallback 仍走每会话窗口。

## 召回块

| 档位 | 字节上限 | 最大会话数 |
|---|---|---|
| `safe` | 2,048 | 3 |
| `aggressive` | 4,096 | 6 |

每个会话**两个槽，回答两个问题**：

- **问题行**：命中查询词最多的用户消息；
- **结论行**：命中词最多且带决策标记的助手消息。结论常不重复问题词（「最后我们定了 40」跟在提到池子的那行之后），因此允许取命中消息后 4 条以内的助手结论（`replyWindow = 4`）。

结论预算 400 字 / 2 条（1 个候选时 1600 / 4，2 个候选时 1000 / 3）。预算不够时**从后往前删证据行**（`Ran:`、`Output:`、`Edit`），证据不能挤掉结论。同会话内按原顺序输出，不按分数顺序——两个结论连读才是叙事。

```text
✓ 历史参考 · 来自 codex 会话 · 2026-11-09
  - Session: **project-name** `00000000-0000-4000-8000-000000000001`
  - 问题: 发版为什么挂了
  - 结论: 网关层 token 过期，改了 session time-to-live

  - 注: 历史参考，不是当前事实；引用前请用当前工具核对。
```

## 跳过什么

- 无关问题 → 输出空（不拿 top-3 凑数）；
- 当前会话及其父子谱系（它已在上下文里）；
- harness 自检、冒烟测试（要求回一个 token、回答就是一个 token）；
- 全部结论都是「被 blocked、无法继续」的会话；
- 说「我没有记忆」的行、plumbing 行、工具调用记录、文档里的单个 bullet；
- 近似重复会话（词集合重合）。
